# SPEC: движок футбольного матча

Точка входа для Claude Code. Этот файл содержит цель, принципы, стек и карту документации. Детали в `docs/`. Перед каждым этапом читай этот файл и документы, указанные для этапа в `docs/09-milestones.md`.

---

## 1. Цель

Построить многофакторный детерминированный движок симуляции футбольного матча и простой визуализатор с кружками, чтобы ответить на четыре вопроса:

1. **Реалистичность расчёта.** Даёт ли движок реалистичные цифры, распределения и пространственную картину матча, а не только правильные средние.
2. **Узнаваемость командных стилей.** Различимы ли стили статистически (классификатор по метрикам) и визуально (по кружкам на поле).
3. **Узнаваемость стилей игроков.** Различимы ли роли и игровые привычки отдельных игроков.
4. **Взаимодействие стилей.** Есть ли между стилями эффект «камень-ножницы-бумага», насколько он сильный на фоне шума, и как стиль сочетается с составом.

### Вне рамок проекта

Развитие игроков, тренировки, возраст, скаутинг, события вне поля, трансферы, лига и сезон, quick-sim, сохранение реплеев, пиксельная графика и анимации. Код не должен готовиться к этим функциям заранее.

## 2. Принципы

1. **Никаких магических чисел в коде.** Все коэффициенты в `config/`, загрузка через serde с проверкой диапазонов, при ошибке падение.
2. **Детерминизм.** Один seed и один конфиг дают один матч, одинаковый в нативной сборке и в WASM. Отдельные потоки PRNG по подсистемам. Вся трансцендентная математика через `libm`, fast-math запрещён. В логике нет `HashMap` со случайным хэшером. Внутри матча нет потоков. Seed матча в пакете выводится из мастер-seed и индекса через SplitMix64. Результаты пакета собираются в вектор по индексу и сворачиваются последовательно.
3. **Слои атрибутов не смешиваются.** Хранение 0–1, влияние через кривые отклика, действия используют только эффективные навыки (`docs/01-data-model.md`).
4. **Каждый фактор влияет в 1–3 местах.**
5. **Исходы физические, где возможно.** Пас летит по физике, перехват определяется тем, кто успел к мячу.
6. **Матчапы не кодируются.** Взаимодействие стилей возникает из позиционирования и оценки пространства. Никаких таблиц «стиль A против стиля B».
7. **Проверяется механизм, а не только результат.** Агрегаты, распределения, пространственная картина и детекторы патологий (`docs/07-validation.md`).
8. **Производительность закладывается сразу** (`docs/02-engine-core.md`, раздел «Производительность»).
9. **Никаких реальных клубов, игроков и логотипов.**

## 3. Стек

- **Ядро на Rust** (stable, edition 2021, Cargo workspace), два таргета: нативный CLI для пакетных прогонов и анализа, WebAssembly для живого запуска в визуализаторе.
- **Визуализатор на TypeScript**: Vite + Canvas 2D, движок в Web Worker через `wasm-bindgen`.
- Крейты: `rayon`, `rand_xoshiro`, `libm`, `glam` (feature `libm`), `serde`, `serde_json`, `clap`, `criterion`, `proptest`, `ts-rs`, `cmaes` или своя реализация CMA-ES.
- Опционально `tools/fit/` на Python для подгонки xG и xT по открытым данным StatsBomb и эталонов компактности по трекинг-данным Metrica Sports. Результат пишется в `config/`.

```
football-sim/
  SPEC.md
  CLAUDE.md                 # создаётся на M0: конвенции и карта docs/
  docs/
  Cargo.toml
  justfile
  config/
    attributes.json  composites.json  response_curves.json
    models.json      physics.json     context.json
    styles/*.json    roles/*.json     traits.json
    targets.json     xt_grid.json     perf.json
    scenarios/*.json
  crates/
    fsim-core/      # мир, физика, восприятие, позиционирование, решения, правила
    fsim-models/    # xG, xT, вероятностные модели, таблицы, кривые
    fsim-gen/       # генератор тестовых составов
    fsim-analysis/  # метрики, валидация, классификаторы стиля, анализ матчапов, отчёты
    fsim-cli/       # бинарь fsim
    fsim-wasm/      # обёртка для браузера
  viewer/           # Vite + TS + Canvas 2D
  data/
    squads/         # сгенерированные составы
    reports/        # HTML-отчёты
  tools/fit/        # Python, опционально
```

## 5. Правила работы для Claude Code

1. Работай строго по этапам из `docs/09-milestones.md`. После каждого этапа: `just check` зелёный, короткий отчёт (что сделано, команды для проверки, ключевые цифры, известные проблемы), остановка до подтверждения.
2. Если для прохождения критерия хочется добавить правило под конкретный матчап или сценарий, остановись и опиши проблему. Обычно исправлять нужно позиционирование или оценку кандидатов.
3. Перед оптимизацией снимай профиль. Не упрощай модель ради скорости без замеров.
4. Не реализуй ничего из списка «Вне рамок проекта».
